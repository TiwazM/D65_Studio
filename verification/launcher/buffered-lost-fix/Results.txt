D65 Studio 0.2.2: buffered SD-image LOST status correction

Hardware observations on ROM 920413:
D65DEMO mounts, lists its directory and loads START. BANK2 fails.
D68B/D68A reads using BANK 128 return decimal 71/2 ($47/$02).
After failure D081/D082 return 64/68 ($40/$44): read-sector; DRQ + LOST.
BANK 0 PEEKs at D000-DFFF instead read RAM, so the initial zero flags
were a diagnostic-command mistake and do not mean no disk was mounted.

Pinned core bc7a3ece8aaee3d4d9f5df09cd71c70b1225a827, sdcardio.vhdl:
ReadingSector at lines 3585-3630 sets LOST on another incoming SD byte
when DRQ is already set, while still writing each byte to the F011 sector
buffer. ReadingSectorAckByte clears BUSY when all 512 bytes are stored.
Our image-only reader waits for completion before consuming the buffer.
Rejecting LOST with the $1C error mask therefore rejects valid buffers.
The mask is now $18: RNF/CRC are fatal; LOST alone is not. Length, chain,
load-address and checksum checks still precede the final commit.
This is not a change for physical-floppy operation, which is unsupported.

Regression: with the core-derived LOST status added to buffered reads,
the original 0.2.1 binary rejects its first valid sector, without DMA.
Changing only CPU $60F5 from 28 to 24 lets it load all 16,384 bytes.
The current diagnostic reader passes the same case; LOST with a checksum
mismatch fails, and LOST with either RNF or CRC still fails immediately.
19 harness cases pass, including no program commit on injected failures.
30 Rust disk/merge/launcher tests pass. The unchanged local WebDAV tests
are blocked by socket permissions in this session (passed previously).
