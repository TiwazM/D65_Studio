BASIC BLOAD SECOND FILE OK. The program has no custom-driver calls.

PASS: Guard rejects a local test copy of ROM 920413 with one altered byte,
error 129, and keeps the original vector. The supplied original ROM is unchanged.
PASS: Guard rejects an existing custom LOAD hook, error 130, leaving that vector

Limits: Xemu cannot mount this 5,570,560-byte D65 format correctly. Controls
contain LEVEL within the first 40 sectors per track and set the D81 test flag
only in their copy of START. The distributed HOOKBAS and HOOKTEST have LEVEL at
T1/S40 and T1/S43 respectively, and leave the test flag zero. Those images still
need hardware confirmation. No arbitrary multi-file game compatibility claimed.
The direct SD-card writer is unchanged, and no SD card is available this turn.

Developer reproduction
----------------------
From the source folder: cargo test --locked.
Reassemble optional binaries: launcher/build-reader.sh /path/to/acme.
Normal Rust builds use the checked-in binaries; users need no assembler/tools.
Assemble suite.a with ACME (-f cbm -o SUITE.prg), or use supplied original PRGs.
cargo run --example compat_fixture -- OUTPUT_DIR verification/load-hook/SUITE.prg
creates HOOKLITE.D65 (D81-control geometry) and HOOKTEST.D65 (extended LEVEL).
Repeat with BASIC.prg for the BASIC pair; rename the full result HOOKBAS.D65.
The test scripts retain the development workspace layout. Adapt roots for a new
checkout. xemu-negative.py expects Xemu and a locally supplied ROM, and creates
only a private test copy. Scripts/PRGs/source are MIT original test material.
probe.c links with Xemu cpu65.c and f011_core.c with CPU_65CE02 and CPU65=cpu.
No Xemu, third-party game, memory dump, or ROM is included in this evidence folder.
